# 封存文件

**這裡的東西已經完成或過期，是設計紀錄，不是待辦清單。**

會搬進來的有兩種：

- **已結案的實作計劃** —— 功能做完之後，計劃本身就從「要做什麼」變成「為什麼這樣做」。
  保留它是因為那些**取捨的理由**在權威文件裡通常只剩結論。
- **時點快照** —— 例如某次 UX 走查的發現紀錄。它記錄的是某個時間的狀態，
  不會被更新，也不該被改寫；下一次走查請產出新的一份。

## 讀這裡的東西時

1. **現況一律以權威文件為準**（`RETRIEVAL.md` / `SCHEMA.md` / `ROUTES.md` /
   `DEVELOPMENT.md` / `SECURITY.md` 與三份 backlog）。封存文件裡的程式碼位置、
   參數名稱、路由都可能已經改了。
2. **不要照著封存的計劃執行。** 裡面的「待辦」都已經做完。
3. 每份檔案開頭都有一段封存說明，寫清楚它完成於何時、現況該去看哪裡。

## 為什麼不直接刪掉

git 記得所有東西，但沒有人會為了理解一個設計而去翻兩個月前的 PR。
留在這裡、並在開頭講清楚它的地位，比「刪掉但假設大家會去 git log 找」實際。

反過來說，**封存不等於可以留著錯的內容**：搬進來的同時要把過時的狀態修正
（例如把「待實作」改成「已完成」），否則它會繼續誤導人，只是換個資料夾誤導。
